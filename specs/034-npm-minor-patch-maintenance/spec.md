# Spec: npm minor and patch maintenance

## Goal

Adopt the grouped Dependabot development-tooling updates while preserving the
repository's existing validation and build behavior.

## Scope

In scope:

- Update `@types/node` from 26.2.0 to 26.4.0.
- Update ESLint from 10.9.0 to 10.9.1 in the lockfile while retaining the
  existing `^10` manifest range.
- Update `eslint-plugin-html` from 8.1.4 to 8.2.0 in the lockfile while
  retaining the existing `^8` manifest range.
- Update html-validate from 11.10.0 to 11.11.0.
- Refresh only the corresponding lockfile entries and dependency snapshots.
- Update the durable dependency-maintenance record and feature memory.

Out of scope:

- Changing lint rules, HTML validation policy, TypeScript configuration, or
  product code.
- Updating unrelated dependencies or regenerating unrelated artifacts.
- Disabling or weakening a check to accommodate the new versions.

## User Stories

### User Story 1

As the repository maintainer, I want the grouped minor and patch tooling
updates verified together so that the validation toolchain stays current
without changing product behavior.

## Acceptance Criteria

1. Given the final manifest and lockfile, when dependency versions are
   inspected, then the four proposed packages resolve to the Dependabot
   versions and unrelated packages remain unchanged.
2. Given the updated Node types and validation tools, when the full preflight
   runs, then type checking, prototype linting, HTML validation, Action
   bundling, distribution validation, formatting, and tests all pass.
3. Given the maintenance-only scope, when the final diff is inspected, then no
   source or validation-configuration file has changed.
4. Given a trusted maintainer request for the final head, when Codex reviews
   the PR, then no unresolved blocking finding remains.

## Negative Scenarios

1. Given an incompatibility in the updated toolchain, when preflight runs,
   then the PR must remain blocked rather than weakening lint, validation,
   type-checking, or test coverage.

## Requirements

- FR-001: Keep the dependency update limited to the four proposed packages and
  their lockfile relationships.
- FR-002: Preserve all validation and product configuration unchanged.
- FR-003: The final head must satisfy the repository's local and GitHub gates.

## Success Criteria

- SC-001: `pnpm install --frozen-lockfile` succeeds on the merged `main` base.
- SC-002: `pnpm run preflight` succeeds with all repository tests passing.
- SC-003: `baseline-checks`, `guard`, `AI Review`, `osv-scan`, and Vercel are
  green before merge.
- SC-004: GitHub reports no unresolved review threads before merge.

## Assumptions

- The lockfile integrity hashes and dependency graph were generated by
  Dependabot from the public package releases named in the PR.
